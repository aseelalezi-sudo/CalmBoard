# ADR-0001: اعتماد Drizzle ORM

- **الحالة:** مقبول
- **التاريخ:** 2026-07-27
- **النطاق:** طبقة البيانات في CalmBoard

## السياق

ينص البرومبت الأصلي على Prisma ORM، بينما المشروع الحالي مبني على Drizzle ORM وتوجد طبقة مخطط ومستودعات واختبارات وترحيلات SQL قائمة بالفعل. يعتمد المشروع كذلك على خصائص PostgreSQL مباشرة مثل Row-Level Security وFull-Text Search وTrigram indexes والفهارس الجزئية.

## القرار

يعتمد المشروع Drizzle ORM رسميا، ولا يُنفذ تحويل إلى Prisma.

يُحصر الوصول إلى Drizzle داخل `packages/database` والمستودعات والخدمات المعتمدة. تبقى عمليات الوصول المباشر الموجودة في تطبيق الويب دينا تقنيا مؤقتا ويجب نقلها تدريجيا إلى المستودعات، لا تكرارها في نطاقات جديدة.

تُدار تغييرات المخطط وفق المسار التالي:

1. تعديل مخطط Drizzle داخل `packages/database/src/schema.ts`.
2. توليد migration قابلة للمراجعة باستخدام `drizzle-kit generate`.
3. مراجعة SQL يدويا، خصوصا تغييرات البيانات وRLS والقيود والفهارس.
4. اختبار الترحيل على قاعدة فارغة ونسخة مماثلة للإنتاج.
5. التطبيق في Staging وProduction باستخدام `drizzle-kit migrate`.

يُسمح بـ`drizzle-kit push` فقط في التطوير المحلي أو قواعد CI المؤقتة، ولا يستخدم في Staging أوProduction.

## الأسباب

- تجنب إعادة كتابة طبقة بيانات مستقرة دون قيمة وظيفية مباشرة.
- المحافظة على تحكم واضح في SQL وخصائص PostgreSQL المتقدمة.
- تقليل مخاطر الترحيل وإعادة الاختبار.
- توافق Drizzle مع نمط المستودعات وTenant Context المستخدم حاليا.
- إبقاء اختيار ORM منفصلا عن أهداف الأمان والعزل والترحيلات.

## النتائج

- هذا القرار استثناء مقصود من اختيار Prisma الوارد في البرومبت الأصلي.
- تظل بقية متطلبات PostgreSQL والعزل وRLS والترحيلات والأداء ملزمة.
- لا تُضاف Prisma أو طبقة ORM ثانية إلى المشروع.
- أي تغيير مستقبلي للـORM يحتاج ADR جديدا وخطة ترحيل مستقلة.
