# مراجعة تحديثات اعتماديات التشغيل — 2026-11-06

طلب #24 الأصلي جمع 29 تحديثًا، لكنه فشل عند تشغيل API المترجم بسبب غياب
`SeverityNumber` من نسخة OpenTelemetry API المفروضة في المشروع.

## القرار

تُقبل تحديثات التشغيل المتوافقة، مع إبقاء الحزم الثلاث التالية على جيل SDK 2:

| الحزمة                                      | النسخة المحتفظ بها                | النسخة المؤجلة |
| ------------------------------------------- | --------------------------------- | -------------- |
| `@opentelemetry/api`                        | `^1.9.1`، مع override إلى `1.9.1` | `^1.10.0`      |
| `@opentelemetry/auto-instrumentations-node` | `^0.81.2`                         | `^0.82.0`      |
| `@opentelemetry/sdk-node`                   | `^0.223.0`                        | `^0.300.0`     |

Sentry 10.78.0 يطلب API ضمن `>=1.9.1 <1.10.0` وSDK tracing من الجيل الثاني.
وفق [دليل ترقية OpenTelemetry الرسمي](https://github.com/open-telemetry/opentelemetry-js/blob/main/doc/3.x/migration-guide.md)،
لا يمكن مزج SDK 2 مع API 1.10؛ لذا فإن تغيير override وحده ليس معالجة صحيحة.
تبقى ترقية SDK 3 مهمة مستقلة، تشمل إصدار Sentry المتوافق، ومتطلبات Node،
واختبار تصدير الإشارات والسياق بين الخدمات.

أُبقي تحديث semantic-conventions المستقل وبقية تحديثات Next.js وNestJS وAWS
وSentry والمحرر وغيرها. بذلك يصبح نطاق الطلب 26 تحديث اعتماد متوافقًا مقترحًا،
مع الحفاظ على تحديثات أدوات التطوير وCI التي دخلت main عبر #20 و#22.
لم تتغير ملفات الترحيلات المنشورة أو استثناءات التدقيق الأمني.

## متطلبات التحقق

أضيفت أربعة اختبارات في `scripts/telemetry-compatibility.test.mjs` تستورد
ملفي instrumentation الفعليين للـAPI والـWorker، مع تفعيل المراقبة وتعطيلها،
وتحمّل Sentry أيضًا. تتحقق الحالة المفعلة من صلاحية سياق span حقيقي ثم
تستخدم مسار الإغلاق الفعلي؛ التصدير إلى console فقط، مع تعطيل مصدري المقاييس
والسجلات وكاشفات الموارد الخارجية، ولا يلزم خادم OTLP أو بيانات اعتماد.

يلزم قبل الدمج نجاح هذه الاختبارات، والتدقيق والأنواع وlint والبناء، ثم فحص
GitHub الكامل بما فيه التكامل والترحيلات والمتصفحات والصور الأربع.
