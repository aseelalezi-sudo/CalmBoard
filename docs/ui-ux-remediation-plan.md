# خطة مراجعة وتطوير واجهات CalmBoard

> آخر تحديث: 2026-08-15
>
> هذا الملف هو المرجع التنفيذي لجودة تصميم الواجهة. لا تُعلّم الشاشة كمكتملة لمجرد نجاح TypeScript أو ظهورها دون خطأ؛ يجب أن تجتاز معايير الاتجاه العربي، الاستجابة، التباين، الحالات، وإتاحة الاستخدام.

## معايير القبول لكل شاشة

- [x] تخطيط واضح في العربية `RTL` والإنجليزية `LTR` دون قلب جزئي للمحتوى.
- [x] تعمل عند عروض 360 و768 و1024 و1440 بكسل دون قص أو تمرير للصفحة كلها.
- [x] شريط عنوان وأدوات متوازن، وتظهر الإجراءات الأساسية قبل الثانوية.
- [x] ألوان دلالية متناسقة في الوضعين الفاتح والداكن، مع تباين مقروء.
- [x] حالات تحميل وفراغ وخطأ ونجاح وصلاحية واضحة وغير تقنية.
- [x] النوافذ والقوائم داخل مساحة العرض، مع إغلاق بلوحة المفاتيح وإدارة صحيحة للتركيز.
- [x] أهداف اللمس لا تقل عن 40 بكسل في الهاتف، ولا تعتمد الوظائف على التحويم فقط.
- [x] النصوص والبيانات التجريبية مترجمة، والأرقام والتواريخ تظهر بالمحلية الصحيحة.
- [x] لا تعرض الواجهة إجراءً غير عامل أو غير مسموح به للمستخدم.
- [x] اختبار منع تراجع مناسب للمشكلة التي تم إصلاحها.

## ترتيب التنفيذ

1. إصلاح المكونات المشتركة أولاً لأن أثرها يمتد إلى معظم الشاشات.
2. إغلاق مشكلات P0: القص، الاتجاه الخاطئ، النوافذ الخارجة، النص غير المقروء، والإجراءات المعطلة.
3. إغلاق مشكلات P1: التسلسل البصري، كثافة المعلومات، الهاتف، وحالات النظام.
4. تنفيذ تحسينات P2: الحركة الدقيقة، الصقل، وتقليل الحمل البصري.
5. بعد كل دفعة: TypeScript ثم الاختبارات ثم ESLint ثم تحقق بصري عربي/إنجليزي متى توفر المتصفح.
